# AtomSpectra Waterfall — прошивка 1.2.29

Релиз (не пред-релиз). Главное — спектр больше не пропадает после перепрошивки при идущем наборе
(issue #58), «Сброс» надёжно доходит до прибора, веб-интерфейс не зависает при нескольких вкладках.

## Исправлено

- **Спектр после перепрошивки или перезагрузки платы при идущем наборе** не показывался, пока прибор
  сам не обнулит время набора (issue #58). Теперь плата сразу показывает весь набор прибора.
- **«Сброс», который прибор не выполнил,** больше не замораживает спектр: плата ждёт подтверждения
  около 10 секунд (на деле 11–13 с после команды), затем показывает набор прибора и пишет об этом строку в журнале главной
  страницы.
- **«Сброс» при отключённом приборе** доходит до прибора при следующем подключении — в том числе
  после перезагрузки платы.
- Если после «Сброса» плата перезагружалась или теряла питание раньше следующего автосохранения
  (около минуты), она могла вернуть спектр, набранный до сброса.
- Очистка спектра при старте теперь доходит до прибора и при идущей записи водопада.
- В водопаде и на графике «Мониторинг» больше не появляется точка со всем накопленным набором
  прибора — после старта без сохранённого спектра или после невыполненного сброса.
- Веб-интерфейс мог перестать отвечать при нескольких открытых вкладках: буферы Wi-Fi и сетевого
  стека теперь размещаются в PSRAM.
- Серийный номер прибора: запрос калибровки перед стартом набора делается и тогда, когда пуст только
  серийник; калибровка, заданная на плате вручную, при этом не заменяется калибровкой прибора.
- Ручное обновление прошивки по Wi-Fi больше не может удалить сохранённый спектр.
- Работа ПК-программы через TCP-мост теперь считается работой с платой: плата не уходит из полевой
  точки доступа, пока по мосту идёт обмен. Клиент моста, пропавший без отключения, освобождается
  примерно через минуту.
- Веб-интерфейс больше не замирает на 1–5 секунд, когда сборщик сегментов подтверждает приём сегмента:
  удаление сегмента выполняется в фоне. Ответ `POST /api/waterfall/segment/delete` теперь
  `{"ok":true,"queued":true}` (или 503, если очередь полна).
- Выгрузка сегментов водопада на сервер (push): на 1.2.28 она могла не проходить совсем — каждая попытка
  обрывалась примерно через 20 секунд. На 1.2.29 выгрузка идёт; проверено на плате, где на 1.2.28 не прошёл
  ни один сегмент. При обрыве передачи журнал теперь показывает настоящий код ошибки (раньше — случайный).
- Сборка из исходников показывает правильную версию (раньше — 1.2.25).
- Обновление прошивки по Wi-Fi при идущей записи теряло до минуты строк водопада: плата перезагружалась,
  не закрыв открытый сегмент. Теперь сегмент закрывается, как при других штатных перезагрузках.
- Первая строка водопада после перезагрузки платы считала часть импульсов дважды. Теперь плата перед
  перезагрузкой сохраняет опору последней строки и считает первую строку от неё.
- «Сброс», который прибор не выполнил, больше не теряет импульсы в водопаде, если прибор сохранил данные.
- Журнал сообщений на главной странице снова виден: раньше он был скрыт, и, например, сообщение о невыполненном
  «Сбросе» не показывалось.
- Мелкие исправления надёжности: досылка `-rst` на живом соединении, `-rst` от ПК-программы через мост
  очищает спектр платы только после доставки прибору, метка «Сброс не доставлен» пишется атомарно, ответ 503 при
  нехватке памяти на печать JSON вместо обрыва, запас стека TCP-моста, объекты JSON в PSRAM.
  Подробности — в `KNOWN_ISSUES.md`.
- Обновление прошивки изредка отвергало корректный образ с ошибкой `set_boot_partition`: повторная проверка
  уже записанного образа ложно не проходила (1 отказ из 25 OTA в журналах испытаний, повтор той же OTA
  прошёл). Теперь эта проверка
  повторяется до 3 раз; отказ первой, полной проверки образа по-прежнему окончателен.

## Известные ограничения

- Пароль полевой точки доступа по умолчанию общеизвестен — смените его на вкладке «Система».
- Веб-интерфейс замирает на время тяжёлых операций (очистка и старт/стоп записи водопада, резервная копия
  настроек, проверка обновления на GitHub, скачивание окна водопада и сегментов); тяжёлые GET-запросы не
  требуют CSRF-токена. Исправление — в 1.2.30, список — в `KNOWN_ISSUES.md`.
- При включённом журнале отладки его выгрузка (`GET /api/debug/log`) временно занимает до ~0.5 МБ памяти.
  Если она совпадёт с автосохранением, свободная память на короткое время опускается ниже 512 КБ.
  Исправление — в 1.2.30.

## Новое в API

- `/api/system`: `int_free`, `int_largest`, `int_min`, `int_dflt_free`, `int_dflt_largest` — внутренняя
  RAM; `heap_walk_us` — время обхода кучи при ответе.
- `/api/status` и `/api/spectrum/meta.json`: `reset_unconfirmed` — сколько «Сбросов» с загрузки платы
  прибор не выполнил.
- `/api/reset`: поле `sent` — дошла ли команда до прибора.
- `/api/status`: `reset_reason`, `reset_reason_code` — причина последнего сброса платы; `boot_count` — номер
  загрузки; `uptime_s`; `elf_sha` — начало SHA256 файла ELF сборки (различает сборки одной версии).
- `/api/system`: `stack_min_free` — минимум свободного стека с загрузки по задачам, байт; `alloc_fail`,
  `alloc_fail_last_size`, `alloc_fail_last_caps` — отказы выделения памяти с загрузки; `cjson_spill` — сколько
  раз память под JSON не нашлась в PSRAM и выделена во внутренней RAM.

## Обновление

- По Wi-Fi: вкладка «Система» → «Обновление прошивки» → «Установить с GitHub», либо вручную
  `atomspectra_gw.bin` через тот же раздел.
- Через USB: `firmware.factory.bin` через `esptool write_flash 0x0`.

## Проверка целостности

Сверяйте `SHA256SUMS.txt` перед установкой.
