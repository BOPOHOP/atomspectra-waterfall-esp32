## Русское резюме (для GitHub-релиза)

### ⚠️ Переход со старых версий (≤1.2.25) — ТОЛЬКО через USB, один раз

Начиная с этого релиза изменилась таблица разделов флеша (появились `ota_0`/`ota_1` для
Wi-Fi OTA). Это меняет физическое расположение раздела LittleFS `storage` на флеше — старое
содержимое (снимки спектра, калибровка) при первой прошивке новой таблицы разделов будет
**стёрто переформатированием**. **Сохраните нужные спектры (вкладка «Сохранённые» → экспорт)
ДО обновления.** Сам переход — одна прошивка целиком по USB (`idf.py flash` или
`flasher_args.json` из комплекта релиза); после неё Wi-Fi OTA (ручная и с GitHub) работает
как обычно для всех последующих обновлений.

### Обновление прошивки по Wi-Fi — вручную (AWF-4)

Страница «Система» → «Обновление прошивки»: выбрать `.bin`, подтвердить — плата пишет образ
в неактивный OTA-раздел потоком (без буферизации всего файла), проверяет магическое число,
chip id и структурную целостность сегментов образа (не только длину тела запроса — она под
контролем клиента и не доказывает целостность сама по себе), затем штатной проверкой
`esp_ota_end()` (SHA-256/подпись) и перезагружается на новый раздел.

### Обновление с GitHub (AWF-5)

Плата теперь может сама проверить и поставить новую версию с
`github.com/VibeEngineering-LLC/atomspectra-waterfall-esp32`, без скачивания файла на
компьютер. На странице «Система»:
- переключатель «Получать предрелизы» (по умолчанию выключен — плата видит только полноценные
  релизы, не `-rcN`);
- кнопка «Проверить на GitHub» — плата обращается к GitHub API, разбирает список из 10
  последних релизов, отбрасывает черновики и (если канал предрелизов выключен) предрелизы,
  выбирает максимальную версию по тегу;
- если версия новее текущей — появляется кнопка «Установить с GitHub»: плата качает образ и
  `SHA256SUMS.txt` того же релиза по HTTPS, сверяет контрольную сумму образа с заявленной в
  `SHA256SUMS.txt` **до** переключения загрузочного раздела, проверяет магическое число/chip
  id/структурную целостность сегментов (тот же код, что и у ручной заливки), и только потом
  ставит образ на загрузку и перезагружается. Любой сбой на любом шаге — установка прерывается,
  активный раздел не меняется, платы не перезагружается.
- Обновления по Wi-Fi с GitHub доступны только начиная с релизов `1.2.26-rc1` и новее — более
  старые версии этого механизма ещё не содержат (ставятся только по USB).
- Работает только при подключении к домашней сети (STA) — в режиме точки доступа
  (Field/Outdoor AP) обновления с GitHub недоступны: платы не видит интернет.

### Время после «Сброс» (из a478475)

Кнопка «Сброс» (и `-rst` по TCP/USB) больше не позволяет часам продолжать отсчёт от старого
набора — время новой сессии считается заново от момента сброса.

### Ускорение /api/spectrum (UI-P1)

Более быстрый форматтер JSON-массива бинов спектра (двойная буферизация, без построчного
`vsnprintf`-цикла) — отдача `/api/spectrum.json` ощутимо быстрее на больших наборах.

### Перекомпоновка вкладки «Система» и Cache-Control (#AWF-6)

Карточки на «Системе» перегруппированы по смыслу (состояние платы, сеть и время, настройки),
Flash/Heap слиты в одну карточку «Плата», «Проверить обновление»/«Установить с GitHub» —
теперь одна карточка внизу; встроенные HTML-страницы прошивка отдаёт с `Cache-Control: no-cache`,
чтобы браузер не показывал закешированную вкладку со старой прошивки после OTA.

## English summary

### ⚠️ Upgrading from ≤1.2.25 — USB only, once

The flash partition table changed in this release (new `ota_0`/`ota_1` slots for Wi-Fi OTA).
This moves the LittleFS `storage` partition's physical location — existing data (saved spectra,
calibration) will be **erased by the automatic reformat** the first time the new partition table
is flashed. **Export any spectra you need (Saved tab) before upgrading.** The transition itself
is a single full USB flash (`idf.py flash` or the release's `flasher_args.json`); after that,
both manual and GitHub Wi-Fi OTA work normally for every later update.

### Manual Wi-Fi firmware update (AWF-4)

System page → "Firmware update": pick a `.bin`, confirm — the board streams it into the inactive
OTA partition, validates the image magic/chip id and per-segment structural completeness (not
just the request body length, which the client controls and does not by itself prove
integrity), then the stock `esp_ota_end()` check (SHA-256/signature), then reboots into it.

### Update from GitHub (AWF-5)

The board can now check and install a new release from
`github.com/VibeEngineering-LLC/atomspectra-waterfall-esp32` on its own, no download to a
computer needed. On the System page:
- a "Receive pre-releases" toggle (off by default — the board only considers full releases,
  not `-rcN` tags);
- "Check on GitHub" — the board queries the GitHub API, parses the 10 most recent releases,
  drops drafts and (channel off) pre-releases, and picks the highest version by tag;
- if a newer version is found, an "Install from GitHub" button appears: the board downloads the
  image and that release's `SHA256SUMS.txt` over HTTPS, verifies the image's checksum against
  it **before** switching the boot partition, and checks magic/chip id/segment completeness
  (the same code path as the manual upload). Any failure at any step aborts the install — the
  active partition is left untouched and the board does not reboot.
- GitHub Wi-Fi updates are only available starting with `1.2.26-rc1` and newer — older releases
  predate the mechanism (USB only).
- Only works on the home network (STA) — in Field/Outdoor AP mode there is no internet, so
  GitHub updates are unavailable there.

### Reset timing (from a478475)

"Reset" (and `-rst` over TCP/USB) no longer lets the clock keep counting from the previous
acquisition — the new session's time starts fresh from the reset moment.

### /api/spectrum speed (UI-P1)

Faster bin-array JSON formatter (double-buffered, no per-line `vsnprintf` loop) — noticeably
quicker `/api/spectrum.json` responses on large datasets.

### System tab regroup and Cache-Control (#AWF-6)

System tab cards regrouped by meaning (board state, network and time, settings); Flash/Heap
merged into one "Board" card; "Check for update"/"Install from GitHub" now live in a single
card at the bottom; embedded HTML pages are now served with `Cache-Control: no-cache` so the
browser stops showing a stale pre-OTA tab after an update.

## Known limitations / что не проверено без живой платы

- Ручная заливка `/api/ota` и приём/установка по Wi-Fi (кнопка «Обновить прошивку») проверены
  вживую: сборки `build-rc1`/`build-rc2` были поочерёдно залиты на тестовую плату, обрезанный
  образ (D1) отклонён без перезагрузки, набор спектра пережил перезагрузку при обновлении.
- **Скачивание релиза с GitHub (rc2) на реальном железе не проверено до публикации этих заметок**:
  реальный `esp_https_ota`-путь через живой GitHub API, редиректы на `objects.githubusercontent.com`,
  реальное время скачивания ~1.6 МБ образа, поведение при обрыве Wi-Fi посреди установки,
  фактическое потребление кучи (замер из кода — не измерение, #AH-1).
- Откат бутлоадера при неуспешной установке (`CONFIG_BOOTLOADER_APP_ROLLBACK_ENABLE=y`) не
  проверен живым power-cycle в этой сессии — только по коду/документации ESP-IDF.
- Host-тесты покрывают только чистую логику (разбор версий/JSON/SHA256SUMS) — HTTP-обработчики
  и фоновая FreeRTOS-задача установки тестируются только компиляцией/статическим анализом.
