# AtomSpectra Waterfall — прошивка 1.2.37

Перестроена страница «Система» и добавлена живая мощность дозы по загруженной кривой.

## Новое

- **Страница «Система»: меню разделов слева.** Разделы: обзор, сеть и время, старт платы, мощность дозы, резервные копии,
  прошивка, опасные действия. Плитки сводки (`tile-board`, `tile-heap`, `tile-flash`, `tile-wifi`, `tile-device`) и обёртки
  `detail-board`, `detail-device`, `detail-wifi` удалены; размер страницы 90 051 Б (было 79 559 Б).
- **Автосохранение настроек на странице «Система».** Изменённая настройка записывается на плату сразу при изменении
  (`saveBootConfig` по `onchange`).
- **Исправлено несохранение галки «Всегда читать калибровку из прибора при старте набора».** Значение галки не
  сохранялось; теперь у неё, как у остальных настроек, запись при переключении (`onchange`), под ней подпись «Применяется
  при следующем старте набора».
- **Живая мощность дозы по загруженной кривой.** Плата считает мощность дозы по кольцу мониторинга за то же окно, что и
  SMA главной (вкладка «Мониторинг», «Интервал усреднения, с»), с коэффициентами по каналам из кривой `dose_curve.csv`;
  без кривой — по коэффициенту `dose_k` (режим `scalar`).
  - `GET /api/spectrum/meta.json?w=<сек>` дополнительно возвращает `dose_rate` (мкЗв/ч или `null`), `dose_mode`
    (`curve`, `scalar`, `none`) и `dose_w` (фактический охват окна, с). Запрос без `w` отвечает по-прежнему, полей дозы в нём нет.
  - Те же поля есть в `GET /api/status` (окно 10 с).
  - Тумблер «Считать живую МД» (страница «Система» → «Мощность дозы», автосохранение; NVS `dose_live_en`, `/api/boot-config`,
    поле `dose_live`, по умолчанию включён): при выключении `dose_mode` = `off`, `dose_rate` = `null`, плата не снимает спектр
    для расчёта и освобождает память кольца доз; действует сразу, без перезагрузки; на главной блок скрыт. Запись `dose_rate`
    в строки водопада не затрагивается.

  - На главной выводится значение `dose_rate`; при `dose_mode: none` блок скрыт, при `null` — прочерк;
    охват окна — во всплывающей подсказке. Если плата отдаёт ответ без `dose_mode` (старая прошивка), главная считает по
    прежней формуле `cps * dose_k`.
  - Кривую можно загрузить и удалить на лету: при смене кривой кольцо доз заполняется «нет данных» (`NaN`, в JSON — `null`),
    расчёт не использует значения старой кривой. Если не хватило внешней памяти (PSRAM) под три буфера, режим `none`,
    предупреждение в журнал один раз, мониторинг продолжает работать.
- **Страница «Система»: защита полей мощности дозы.**
  - Поле коэффициента `k`: пустое, нечисловое или отрицательное значение не отправляется на плату (прежнее `k` остаётся),
    показывается «Введите число ≥ 0»; явный ввод `0` сохраняется, с пометкой, что без кривой мощность дозы отключается (`none`).
  - Загрузка кривой, в которой плата не нашла ни одной допустимой точки (`{"ok":true,"n":0}`), показывается как ошибка,
    а не «Загружено: 0 точек». Прежняя кривая при этом уже перезаписана (см. KNOWN_ISSUES).
  - Статус кривой и подсказка в меню «Мощность дозы» больше не сбрасываются в «кривая не загружена» при смене языка.
- **Подпись «Ср. CPS за набор»** (en: «Avg CPS per run») на главной вместо «Ср. CPS (реал.)».
- Заголовок `X-Hist-Age-Ms` в ответе `GET /api/spectrum.json` (мс с приёма последней гистограммы платой на момент ответа; `-1` — не было ни одной с загрузки; тело ответа и прочие ручки не менялись); README: раздел для клиентов REST/TCP (единицы и смысл полей `spectrum.json`, кэш 2 с, модель владения прибором), в таблице Web API убрана пустая строка, разрывавшая таблицу.

## Что не вошло и ограничения

- **Защита загрузчика кривой от файлов формата `dosecurve-v1` (по энергии) не реализована (#MX-17).** Загрузчик
  трактует первую колонку как номер канала; кривая в энергиях принимается молча и считается неверно. См. KNOWN_ISSUES.
- Загрузчик кривой принимает `k = inf` (проверяется только `k >= 0`). См. KNOWN_ISSUES.
- `GET /api/spectrum.json` поле мощности дозы не содержит; оно есть только в `meta.json?w=` и `/api/status`.
- Не проверено на плате: цена пересчёта дозы раз в секунду и влияние на `hist_drop`/`usb_rx_err` за час; фрагментация PSRAM
  при многократной загрузке кривой; доля `NaN`-отсчётов и `dose_w` ≥ 0,95 · `w` на окнах 60–600 с; сверка `dose_rate`
  длинного окна со строками водопада; POST `dose_curve` и «Сбросить кривую» на живой плате; плата на другом чипе (S3).
- `X-Hist-Age-Ms` на живой плате не проверялся (host-тесты и сборка); не проверено, присылает ли прибор гистограммы после `-sto`.
- Не проверено в браузере: блок дозы на главной и перестроенная страница «Система» глазами (отдача страниц и синтаксис
  скриптов проверены); автосохранение настроек отправкой реальной записи (POST) не проверялось.
- 4 мутанта `mutate_wiring_f01.sh` (`M105_mx7_nodays`, `MI4_size`, `MI12_no_csrf`, `MI17_tmp_name`) не применяются:
  устаревшие якоря, так же на предыдущем коммите.
