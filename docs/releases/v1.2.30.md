# AtomSpectra Waterfall — прошивка 1.2.30

Релиз (не пред-релиз). Главное — веб-интерфейс не замирает на время тяжёлых операций: старт, стоп и очистка
водопада, скачивание окна и сегментов, проверка обновления на GitHub теперь выполняются вне основного потока
веб-сервера. «Сброс» больше не теряет последнюю строку водопада.

## Исправлено

- **«Сброс» дописывает последнюю строку водопада.** Перед отправкой команды сброса плата сохраняет в водопад
  строку за время, прошедшее с прошлой записи (раньше до 5 с импульсов перед сбросом в водопад не попадали).
  Ограничение из 1.2.29 снято.
- **Старт, стоп, очистка водопада и удаление сегмента** выполняются в отдельной задаче: веб-интерфейс,
  опросы статуса и WebSocket-кадры не ждут завершения операций с флеш-памятью (раньше — секунды, при очистке
  нескольких сегментов — десятки секунд). Ответы прежние; если предыдущая такая операция ещё идёт,
  ответ — 503 с заголовком `Retry-After: 2`.
- **Скачивание окна водопада и экспорт** (`/api/waterfall/window`, `export.aswf`, `export.n42`, отдача
  сегмента) — тоже в отдельной задаче, по одному скачиванию за раз (иначе 503 с `Retry-After`).
- **Страница водопада при открытии забирает последние 64 строки**, а не всё кольцо (до 4 МБ). Параметр
  `?rows=N` у `/api/waterfall/window` ограничивает число последних строк; без параметра — всё кольцо, как раньше.
- **Проверка обновления на GitHub** не занимает веб-сервер на время запроса: плата запускает проверку в фоне,
  страница «Система» опрашивает результат (ответ `{"state":"checking"}` пока идёт проверка).
- **Журнал отладки** (`GET /api/debug/log`) отдаётся потоком по кускам по 8 КБ и больше не копирует всё кольцо
  в память (раньше — до ~0.5 МБ на время выгрузки; об ограничении сказано в 1.2.29).
- **WebSocket**: кадры отброшенного клиента из очереди больше не ждут сокетный таймаут, очередь на клиента
  сокращена с 8 до 4 кадров.
- **Резервная копия настроек** (`/api/settings/backup|snapshot`): ожидание прибора в веб-сервере сокращено
  с 2 секунд до 1 секунды на попытку.
- **Безопасность (CSRF).** Тяжёлые GET-запросы `/api/ota/github/check`, `/api/settings/backup` и
  `/api/waterfall/window` требуют заголовок `X-CSRF-Token` (веб-интерфейс подставляет его сам). Внешним
  клиентам, вызывающим эти три адреса напрямую, нужно получить токен так же, как для POST-запросов.
- **Клиент выгрузки сегментов** (`scripts/wf_pull_client.py`): сегмент с уже встречавшимся именем и размером,
  но другим содержимым, больше не считается «уже забранным» (раньше плата могла удалить непринятые данные).
  Файл с иным содержимым сохраняется с суффиксом `.dupN`.
- Страница водопада показывает отказ загрузки настроек выгрузки и сообщает о не-200 ответе старта/стопа;
  свёртка строк в журнале главной страницы больше не теряет счётчик «(+N)» при длинной первой строке.

## Для разработчиков

- Диагностический образ (не для релиза): `scripts/build_diag.sh` — паника по сторожевому таймеру задач,
  статистика задач, контроль порчи кучи, посмертный дамп во флеш-раздел `coredump` (своя таблица разделов,
  раздел хранения на 64 КБ меньше).

## Известные ограничения

- Пароль полевой точки доступа по умолчанию общеизвестен — смените его на вкладке «Система».
- Резервная копия настроек: полного снятия блокировки нет — короткое ожидание прибора (до 1 с на попытку)
  остаётся в веб-сервере.
- Одновременно идёт одна выдача (окно, экспорт, сегмент) и одна операция управления; параллельный запрос
  получает 503 с `Retry-After: 2`. Экспорты и отдача сегмента не требуют CSRF-токена. Подробности — в
  `KNOWN_ISSUES.md`.
