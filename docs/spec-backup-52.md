# Спека: автоматические резервные снимки спектра (issue #52)

**Дата:** 2026-09-07. **База:** `main` = `e90cd93` (v1.2.22). **Целевая версия:** 1.2.23.
**Ветка:** `feat/backup-52`.

## Постановка (issue #52, автор Verter73, 2026-08-25)

На плате без microSD: хранить «X последних спектров, каждые Y часов, с префиксом ZZZ».
Сценарий: уехал на месяц, питание рубанули; если стоит автозапуск набора при подаче
питания — новые снимки должны идти уже под новым именем, чтобы не смешаться со старыми.

Решения оператора 07.09: (1) префикс общий (`name_prefix`, #FW-42) + автосуффикс сессии;
(2) первый снимок — через Y после загрузки, не сразу; (3) сегменты водопада на стенде можно
стирать.

## Проект

### Хранение
- Каталог `/storage/bk/`, файлы `bk_<sess>_<seq>.bin`, тело — `spectrum_data_t` как в `spec_`.
  Структуру `spectrum_data_t` НЕ менять (сломает `current.bin`, `calib`, все `spec_`).
- `sess` — номер сессии платы: NVS `boot/sess` (u32), инкремент при каждой загрузке
  (`boot_config_bump_session()` в `main.c` до старта USB). Так после потери питания
  снимки получают новое имя без участия человека.
- `seq` — порядковый номер снимка в сессии, с 1, счётчик в RAM.
- Ротация: перед записью, пока файлов ≥ X — удалить самый старый по паре (sess, seq).
  Ручные `spec_` не трогаются никогда.
- Резерв места — как в `spectrum_save_to_flash` (`AUTOSAVE_RESERVE` = 1 МБ).

### Настройки (NVS ns `boot`)
| Ключ | Тип | Диапазон | Смысл |
|---|---|---|---|
| `bk_n` | u8 | 0..20, 0 = выкл (дефолт) | X — сколько хранить |
| `bk_h` | u16 | 1..168, дефолт 24 | Y — период |
| `bk_tm` | u8 | 0/1, дефолт 0 | тестовый режим: Y в минутах (только API, в UI нет) |
| `sess` | u32 | — | счётчик сессий (read-only через API) |

### Планировщик (`main.c`, существующий 10-с цикл)
- `backup_tick` считает тики; порог `bk_h*360` (или `bk_h*6` при `bk_tm`).
- По достижении порога: если `bk_n>0 && usb_host_cdc_is_connected() && sp->valid &&
  sp->total_time_sec>0` и `http_io_gate_try_enter()` — `spectrum_backup_save(sess, bk_n)`,
  `leave`, `backup_tick=0`. Гейт занят — повторить на следующем тике, счётчик не сбрасывать.
  Спектр невалиден — сбросить счётчик (ждать следующий период).
- Запись 33 КБ идёт в случайной фазе USB, как и ручной «Сохранить» (`handle_save`); привязку
  к коммиту свипа (#FW-13) не делаем — раз в часы, не раз в минуту. Отметить в KNOWN_ISSUES.
- Изменение настроек применяется на лету: `boot_config_load` в тике каждые 60 тиков дорого?
  Нет — `handle_boot_config_set` дёргает `backup_sched_reload()`; в цикле читаются статики.

### Чистая функция (host-тестируемая)
`main/backup_plan.h/.c`, без ESP-зависимостей:
```c
typedef struct { uint32_t sess, seq; } backup_id_t;
bool backup_parse_name(const char *name, backup_id_t *out);   // "bk_3_12.bin" → {3,12}; иначе false
int  backup_rotate_plan(const backup_id_t *have, int n, int keep,
                        backup_id_t *to_delete, int cap);       // сколько и какие удалить,
                                                                // чтобы после добавления одного
                                                                // осталось ≤ keep
```
Порядок старшинства: меньший `sess`, при равном — меньший `seq`. `keep<=0` → удалить все.

### API
- `GET/POST /api/boot-config` — + `backup_keep` (X), `backup_hours` (Y), `backup_test_minutes`
  (bool), `session` (только GET). Валидация диапазонов, вне диапазона → 400.
- `GET /api/list` — + массив `backups`: `[{name:"bk_3_2",session:3,seq:2,counts,time,saved_at}]`,
  плюс поле `session` (текущая). Обратно совместимо (поле `spectra` без изменений).
- `GET /api/backup/<name>/export.xml|export.csv|spectrum.json` — имя проверяется
  `backup_parse_name` (никаких `/`, `..`), рендеры общие с saved.
- `POST /api/backup/<name>` — удалить (CSRF, гейт).
- Имя экспорта: `web_build_export_name(<prefix>, "S<sess>_<seq>.<ext>")` →
  `ZZZS3_2.xml`; с пустым префиксом — `S3_2.xml`.

### UI
- `system.html`, блок «Старт платы» → новая карточка «Резервные копии спектра»: поле X (0..20,
  0 = выкл), поле Y часов (1..168), подсказка про сессии; сохраняется той же кнопкой.
  i18n ru/en.
- `saved.html`: вторая группа «Автоматические копии» — имя `S<sess>_<seq>`, дата, счётчики,
  кнопки xml/csv/удалить. Текущая сессия — в шапке группы.

### Версия и документация
`version.txt` → 1.2.23; README (ru/en) раздел «Резервные копии»; KNOWN_ISSUES — фаза записи.

### Ответ на пункт «требует толкования»

**Вопрос:** после потери питания плата продолжает накапливать спектр или начинает заново?
**Замер:** сразу после перезагрузки живой спектр показал `time=711 c` при `uptime_sec=458 c`.
**Вывод:** набор ПРОДОЛЖАЕТСЯ — `spectrum_restore_autosave()` поднимает `current.bin`, и снимок
новой сессии содержит в том числе накопленное до сбоя. Отдельный снимок «перед сбросом» при
`clr_spec` не нужен: очистка спектра при старте — осознанный выбор пользователя, и он описан в
README вместе с этим следствием.

## Риски
- LittleFS общий с водопадом: 20 × 33 КБ = 660 КБ, резерв 1 МБ уже учитывается.
- Часы без интернета = 1970: в имени файла даты нет намеренно, `saved_at` внутри файла.
- Смена структуры `spectrum_data_t` запрещена (см. выше).
