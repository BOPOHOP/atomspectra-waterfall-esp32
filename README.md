# AtomSpectra → ESP32-S3 → Web UI

**🇷🇺 Русская версия** · [🇬🇧 English](README.en.md)

WiFi-шлюз для гамма-спектрометра **KB Radar «Atom Spectra»** на ESP32-S3 с USB OTG Host.

Подключается к спектрометру по **USB** (не BLE!), принимает 8192-канальный спектр
в реальном времени и показывает его в браузере — с осями, логарифмической шкалой,
энергетической калибровкой в keV и экспортом в форматы **BecqMoni**, **InterSpec**,
**N42.42** и **ЛСРМ**.

![ESP32-S3](https://img.shields.io/badge/ESP32--S3-N16R8-blue) ![ESP-IDF](https://img.shields.io/badge/ESP--IDF-v5.4-green) ![USB](https://img.shields.io/badge/USB-OTG%20Host-orange) ![Channels](https://img.shields.io/badge/Spectrum-8192%20ch-purple)

## Что это решает

Программа **AtomSpectra** для ПК — отличная, но требует прямого USB-подключения
спектрометра к компьютеру. Этот шлюз превращает ESP32-S3 в **WiFi-мост**:

- спектрометр подключён к ESP через USB — маленькая плата рядом с прибором;
- спектр доступен **в любом браузере** по WiFi — без проводов к ПК;
- **BecqMoni XML** скачивается одним кликом — открывается в [BecqMoni](https://github.com/Am6er/BecqMoni) напрямую;
- **InterSpec CSV** — для [InterSpec](https://sandialabs.github.io/InterSpec/) от Sandia;
- **N42.42** (`RadInstrumentData`) и **ЛСРМ `.spe`** — индустриальный N42 и формат SpectraVibe для гамма-анализа;
- **TCP-мост** (порт 8234) — BecqMoni / AtomSpectra на ПК могут подключиться через WiFi вместо COM-порта;
- спектры **сохраняются на flash** (до ~400 штук) — можно копить и экспортировать позже.

Никаких облаков. Никаких аккаунтов. Всё работает в локальной сети.

## ⚠ Перед использованием

Шлюз подключается к спектрометру по USB и шлёт ему штатные команды управления
(`-inf`, `-sta`, `-rst`). При включённой опции «очистка спектра на старте» плата
пошлёт прибору `-rst` — **накопленный в приборе спектр будет стёрт**.

- Сохраните важные накопленные спектры штатным ПО AtomSpectra на ПК **до**
  подключения прибора к шлюзу.
- Прошивка/OTA самой платы ESP32 прибора не затрагивает, но прерывание прошивки
  может потребовать повторной заливки через USB.

## Отказ от ответственности

Прошивка предоставляется «как есть», без каких-либо гарантий. Автор не несёт
ответственности за любой прямой или косвенный ущерб: сброс накопленных данных или
настроек прибора, потерю данных, неработоспособность устройства или платы.
Используя прошивку, вы принимаете эти условия и действуете на свой страх и риск.

### Резервные копии спектра

Плата умеет сама сохранять спектр на flash с заданным периодом и держать только
несколько последних снимков. Это для длинных измерений без присмотра: уехали на месяц,
питание пропало — после включения набор продолжится с последнего автосохранения, а снимки
останутся на flash.

Настраивается на вкладке **«Система» → «Резервные копии спектра»**:

| Параметр | Значение |
|---|---|
| Хранить снимков | 0…20; **0 — выключено** (значение по умолчанию) |
| Снимать каждые | 1…168 часов |

Как это работает:

- Первый снимок делается **через заданный период** после включения, не сразу.
- Снимок берётся, только если прибор подключён и спектр непустой; иначе период
  пережидается — пустых файлов на flash не появляется.
- Когда снимков становится больше заданного числа, самый старый удаляется.
  **Ротация трогает только автоматические снимки**; спектры, сохранённые кнопкой
  «Сохранить», не удаляются никогда.
- У каждой загрузки платы свой **номер сессии**, и он входит в имя снимка
  (`S3/2` — вторая копия третьей сессии). Поэтому после пропадания питания новые
  снимки не смешиваются со старыми, и переключать ничего не нужно. Текущий номер
  виден на вкладке «Система».
- **Что именно попадёт в снимок после сбоя питания.** Плата автосохраняет текущий
  спектр раз в минуту и при следующем включении его восстанавливает, поэтому набор
  продолжается, а не начинается с нуля (теряется до минуты). Снимок новой сессии
  содержит и то, что было накоплено до сбоя. Если такое склеивание нежелательно —
  включите «Очищать спектр при старте» на той же вкладке: тогда каждая сессия
  начинается с чистого спектра. Проверено на плате: после перезагрузки время набора
  живого спектра (711 с) превышало аптайм платы (458 с).
- Имя выгрузки — `S<сессия>_<номер>.csv` с общим префиксом файлов (`boot.exportPrefix`),
  если он задан.

Место: один снимок — 33 КБ, максимум 20 штук — 660 КБ на разделе 12,9 МБ. Снимок не
делается, если свободного места меньше 1 МБ.

## Экспорт

### BecqMoni XML (`/api/export.xml`)

Полный 8192-канальный спектр в формате `ResultDataFile` (FormatVersion 120920):
- `EnergyCalibration` — полиномиальные коэффициенты из прибора
- `ValidPulseCount` / `TotalPulseCount` / `MeasurementTime` / `LiveTime`
- 8192 `<DataPoint>` элементов
- Совместим с BecqMoni: File → Open → выбрать скачанный `.xml`

### InterSpec CSV (`/api/export.csv`)

Заголовки с калибровочными коэффициентами, серийным номером, временем:
- `calibcoeff` — полином калибровки
- `livetime` / `realtime` — реальное и живое время (с учётом мёртвого времени детектора)
- 8192 строк `channel, count` (1-based)
- Совместим с InterSpec: File → Open → выбрать `.csv`

### ANSI N42.42 (`/api/export.n42`)

Спектр в индустриальном XML-формате `RadInstrumentData` (стандарт ANSI/IEEE N42.42):
- `EnergyCalibration` с коэффициентами полинома из прибора
- `RealTimeDuration` / `LiveTimeDuration` (ISO-8601, `PT…S`)
- `ChannelData` — 8192 значения
- Импортируется в InterSpec, Cambio и другое ПО с поддержкой N42

### ЛСРМ `.spe` (`/api/export.spe`)

Спектр в текстовом формате ЛСРМ (используется в [SpectraVibe](https://github.com/Am6er)):
- секции `$SPEC_ID:` / `$MEAS_TIM:` (live realtime) / `$DATA:` / `$ENER_FIT:`
- 8192 канала по одному значению на строку
- удобно для гамма-анализа в инструментах, читающих формат ЛСРМ

## Режимы сети: Indoor и Outdoor

Плата работает в двух режимах. Переключатель **Indoor / Outdoor** виден сразу в шапке
стартовой страницы.

**🏠 Indoor (STA)** — как описано выше: плата — клиент домашней WiFi-сети, спектр
доступен по `http://<IP-платы>/`, время берётся по SNTP из интернета, сегменты
водопада автоматически выгружаются приёмнику.

**🌲 Outdoor (полевой AP)** — плата **сама становится точкой доступа Wi-Fi**, роутер и
интернет не нужны. Это режим для измерений в поле, когда с собой только телефон (и, по
желанию, повербанк для питания платы):

- **SSID** `AtomSpectra-Outdoor`, **пароль** `atomspectra` (WPA2-PSK), **адрес** `192.168.4.1`;
- телефон подключается к этой сети — и получает **полный** Web UI платы: живой спектр,
  водопад, экспорт (N42/XML/SPE/CSV), управление прибором (`-sta`/`-sto`/`-rst`),
  калибровка, сохранение спектров;
- данные водопада всё это время копятся на flash самой платы (раздел LittleFS) —
  забираются потом дома, в режиме Indoor, приёмником;
- всё работает офлайн: ни SNTP, ни выгрузки наружу, ни облака.

**Что происходит при подключении (captive-landing).**
Как только телефон присоединяется к `AtomSpectra-Outdoor`, операционная система делает
свою обычную «проверку связи» (Android — `generate_204`, iOS/macOS — `hotspot-detect`,
Windows — `ncsi`). Плата отвечает на неё **лёгкой страницей входа**, и телефон показывает
привычное уведомление **«Вход в сеть»** (как в кафе или аэропорту). На этой странице
**крупно выведен адрес прибора** — `192.168.4.1` и `atomspectra.local` — и она **сама, за
~1 секунду, открывает страницу прибора**; там же кнопка «Открыть прибор →».

- Страница входа **нарочно лёгкая** (без внешних шрифтов и скриптов), чтобы гарантированно
  отрисоваться в упрощённом «captive-браузере» телефона, где тяжёлый основной интерфейс
  иногда не догружается.
- Если авто-переход не сработал (встроенный браузер iOS умеет ограничивать переходы) —
  **адрес остаётся на экране**: откройте Safari/Chrome и введите `192.168.4.1` вручную.

**Как войти в Outdoor:**

1. **Переключателем** Indoor → Outdoor в шапке стартовой страницы. Плата перезагрузится и
   поднимет точку доступа; это **«липкий»** режим — сохраняется между перезагрузками, пока
   не переключите обратно;
2. **Автоматически (fallback)** — если домашняя сеть недоступна ≥ 5 мин, плата сама поднимает
   полевой AP **одноразово**: следующая перезагрузка снова пробует домашнюю сеть. Удобно,
   когда унесли плату из зоны роутера, не трогая настройки;
3. **С новой (ненастроенной) платы** — в setup-портале кнопка **«Полевой режим (Outdoor)»**.

Возврат в Indoor — тем же переключателем в шапке (а для fallback-режима достаточно
перезагрузки в зоне домашней сети). Возврат из fallback-AP ждёт, пока на веб-сервере
платы стихнет HTTP-активность (10 минут) — просто подключённый к точке телефон
(например, сохранённая Wi-Fi-сеть на телефоне сама переподключилась) возврат не блокирует.

**Настройка «Переходить в полевую точку доступа при потере Wi-Fi»** (Система → Старт
платы → Сеть, `/api/boot-config`) — **по умолчанию ВЫКЛЮЧЕНА** (решение оператора;
отсутствующий ключ в NVS, например после апгрейда, тоже означает выключено). Выключенная,
плата во время работы реконнектит бесконечно с нарастающей паузой (потолок 60 с), в Field AP
не уходит. Страховка сохраняется в любом случае: если с момента включения/перезагрузки Wi-Fi
ни разу не заработал 5 минут подряд, плата всё равно поднимет полевой AP — иначе после смены
пароля или роутера до неё было бы не достучаться. Включённая — плата уходит в Field AP через
те же 5 минут без роутера и возвращается сама, когда роутер снова виден и с платой никто не
работает 10 минут. Применяется сразу, без перезагрузки. Полная картина — в таблице ниже.

### Wi-Fi: что делает плата при пропадании роутера

| Ситуация | Настройка ВЫКЛ (по умолчанию) | Настройка ВКЛ |
|---|---|---|
| Роутер пропал < 5 мин (перезагрузка роутера) | Переподключается по расписанию, ничего не меняется | То же |
| Роутер пропал > 5 мин | **Не** уходит в Field AP, переподключается бесконечно (пауза до 60 с) | Уходит в `AtomSpectra-Outdoor`, возвращается сам, когда роутер снова виден **и** 10 минут никто не работает с веб-страницей платы |
| Общий сбой питания (роутер и плата обесточились одновременно) | Если после включения питания Wi-Fi не поднялся 5 минут подряд — **страховка**: плата всё равно поднимает Field AP (иначе до неё не достучаться) | То же |
| Сменили пароль Wi-Fi или сам роутер | Восстановление: выключить и включить питание платы → через 5 минут страховка поднимет `AtomSpectra-Outdoor` (пароль по умолчанию `atomspectra`, адрес `192.168.4.1`) → зайти и настроить Wi-Fi заново | То же |

**Рекомендация:** там, где роутер часто перезагружается или плата стоит на границе покрытия — оставьте настройку **ВЫКЛ** (значение по умолчанию): плата не будет плодить точки доступа на каждый короткий сбой. Сохранённая на телефоне сеть `AtomSpectra-Outdoor` (телефон подключается к ней сам, когда видит) возврату **не мешает**, пока не открыта веб-страница платы — блокирует только реальная работа с UI/API (см. выше).

**Полевой сценарий целиком:** дома в Indoor настроили запись водопада → переключили в
Outdoor → взяли плату + телефон (+ повербанк) в поле → телефон к `AtomSpectra-Outdoor` →
всплыла страница с адресом → работаете со спектром и водопадом → дома вернули Indoor →
приёмник забрал накопленные сегменты водопада с flash платы.

### Время в полевом режиме

В Outdoor нет интернета → SNTP не работает. Время платы приходит **от браузера
телефона** автоматически при открытии любой страницы (и раз в час). Ручная коррекция —
поле `datetime-local` в разделе **Система**. При активном SNTP (дома) ручная/браузерная
установка игнорируется — источник времени не воюет сам с собой.

Экспорт (N42/XML/spe/CSV) со дня записи, когда время ещё не пришло (часы = 1970),
помечается «TIME NOT SYNCHRONIZED» и не портит нормальные записи.

### Пароль полевой точки доступа

Пароль по умолчанию `atomspectra` — **публичный, документированный**. Через открытый AP
управляется прибор (включая `-rst`, стирающий спектр) — для людных мест **смените
пароль** в разделе **Система** (поле пароля AP + подтверждение; применяется после
ребута). При дефолтном пароле Web UI показывает предупреждение.

### BT/BLE

Плата работает **только по USB** (к спектрометру) **и WiFi**. Bluetooth/BLE не
используется и **не собирается** (`CONFIG_BT_ENABLED=n`): BLE-радио ESP32-S3 не
инициализируется ни в одном режиме, RAM и питание не расходует.

## Спектр после отключения питания

Анализатор (питается от платы по USB) сбрасывает свою внутреннюю гистограмму и часы
при любой потере питания. Плата детектирует такой сброс и **сворачивает** накопленный
до этого момента спектр в **базу**, а свежую (обнулённую) гистограмму прибора
показывает поверх неё — в Web UI набор выглядит непрерывным.

- **Что теряется:** только то, что накопилось **между последним автосохранением и
  обрывом питания** — автосейв идёт раз в ~60 секунд, значит теряется **до ~60 секунд**
  набора (худший случай — обрыв сразу после автосохранения). Всё, что было сохранено
  до этого момента, восстанавливается в базу при следующей загрузке.
- **`/api/status`**: `base_counts`/`base_time` — сколько накоплено в базе, `dev_resets` —
  сколько раз плата поймала сброс прибора за время работы, `reset_unconfirmed` — сколько
  «Сбросов» прибор не выполнил (`firmware-v1.2.29+`): если примерно за 10 с после «Сброса» (по расчёту 11–13 с) прибор
  продолжает присылать старый набор, плата показывает его, а не держит экран пустым; журнал
  на главной странице пишет об этом строку.
- **Кнопка «Сброс»** (в Web UI **и** в BecqMoni/AtomSpectra через TCP-мост, см. ниже) —
  единственный способ действительно обнулить показания; сам факт пропадания питания
  базу не трогает, наоборот — сохраняет в неё то, что уже было набрано.

### REST-режим: сведения для клиентов

Раздел для разработчиков программ, которые опрашивают плату по HTTP. Описание составлено по исходному коду прошивки 1.2.37;
то, что на живом приборе не измерялось, помечено прямо.

**Поля `GET /api/spectrum.json`**

| Поле | Тип, единица | Смысл |
|---|---|---|
| `bins` | массив из 8192 целых, отсчёты | Число отсчётов в каждом канале; к набору прибора добавлена база (см. «Спектр после отключения питания»). Длину повторяет поле `channels` |
| `total` | целое, отсчёты | Сумма отсчётов того же спектра (с базой) |
| `time` | целое, с | Время набора с учётом базы; целые секунды |
| `live` | число с одним знаком, с | Живое время: `time` за вычетом оценки мёртвого времени `(RISE+FALL+1)/F` на импульс (параметры из `-inf` прибора); пока параметры не получены, равно `time` |
| `dead` | 0 или 1, **флаг** | Не мёртвое время. `1` — USB открыт, кадры FTDI идут (последний принят менее 4 с назад), с открытия порта прошло 6 с и больше, но с момента открытия не принят ни один пакет прибора; первые 6 с после открытия порта флаг не выставляется |
| `cpu` | целое, % | Загрузка процессора прибора из пакета статуса |
| `cps` | целое, имп/с | Значение, которое сообщает прибор; интервал его усреднения в коде платы и в `PROTOCOL.md` не указан. Скорость счёта по спектру можно оценить и самостоятельно: разность `total` к разности `time` между запросами |
| `lost` | целое, импульсы | Число потерянных импульсов из пакета статуса прибора |
| `calib`, `calib_set` | массив чисел; булево | `calib` — коэффициенты c₀…c_k полинома `E(ch) = c₀ + c₁·ch + …` (энергия в кэВ, `ch` — номер канала); поле есть, только когда калибровка признана действительной (`calib_valid`). `calib_set: false` — калибровка не задана: она недействительна (`calib_valid` ложно), либо коэффициенты нечисловые, либо все нулевые |
| `hist_ok` | целое, шт. | Счётчик полных гистограмм (8192 канала), опубликованных платой с её загрузки. Растёт не строго на 1 за гистограмму прибора: гистограмма, коммит которой плата отложила из-за неоднозначности сброса, пропускается целиком (в `hist_ok` и в `hist_drop` не входит), а публикуется следующая гистограмма прибора; поэтому `hist_ok + hist_drop` — не число принятых гистограмм. Обнуляется только перезагрузкой **платы**; `-rst` и `POST /api/reset` его не сбрасывают |
| `hist_drop` | целое, шт. | Число гистограмм, отброшенных с загрузки платы: неполных (разрыв между фрагментами) и принятых во время сброса спектра |

Остальные поля (`bridge_drop`, `usb_rx_err`, `rx_ring_drops`, `autosave_age_sec`, `autosave_fail_streak`, `t1`–`t3`, `serial`,
`reset_unconfirmed`) диагностические и здесь не описываются.

**Кэш и частота опроса.** Тело ответа собирается из одного снимка и кэшируется на 2 с (раньше срока кэш сбрасывается при смене
калибровки). Опрос чаще одного раза в 2 с новых данных не даёт; `time` к тому же идёт целыми секундами.

**Заголовки ответа `GET /api/spectrum.json`**

- `X-Spectrum-Render-Count` — номер поколения кэша (целое); общий у `spectrum.json`, `/api/spectrum` и `meta.json` одного поколения.
- `X-Hist-Age-Ms` (с 1.2.37) — целое, мс: сколько прошло с приёма платой последнего пакета гистограммы **на момент ответа**
  (а не сборки закэшированного тела); `-1` — с загрузки платы не принято ни одного. Гистограмма передаётся фрагментами, штамп
  обновляет каждый принятый фрагмент, поэтому он может обновиться раньше, чем вырастет `hist_ok`. Заголовок сообщает только факт
  приёма; идёт ли набор, клиент решает сам (например, по порогу возраста и росту `time`). Присылает ли прибор гистограммы
  после `-sto`, на приборе не проверялось.
- `X-Spectrometer-Dead` (`1`/`0`, то же, что `dead`) — только в ответе 404 (его же отдают `/api/spectrum` и `meta.json`).

**Ответы.** `404` с текстом `No spectrum data yet` означает «данных нет»: после загрузки платы или после сброса спектра ещё не
опубликована новая гистограмма. Сброс (`POST /api/reset`) кэш тела не очищает: в течение до 2 с после сброса `spectrum.json` может
ответить `200` со спектром, собранным до сброса (заголовок `X-Hist-Age-Ms` при этом считается на момент ответа и о возрасте
тела не говорит); `404` клиент увидит лишь после истечения кэша и до публикации новой гистограммы. Ответ на команду
прибора в ответе `POST /api/command` не приходит: тело — `{"ok":true}` либо `{"ok":false}` при коде 200 (`true` — команда
записана в USB без ошибки; подтверждения от прибора нет). Текстовый ответ прибора ищите в `GET /api/devlog?since=N`:
`{"up_ms":…,"lines":[{"seq":…,"t":…,"text":"…"}],"next":M}`, `t` и `up_ms` — миллисекунды платы; журнал хранит последние 8 строк,
поэтому опрашивать его следует с `since=<прежний next>`. `POST /api/reset` отвечает `{"ok":true,"sent":true|false}` (`sent:false` —
прибору `-rst` не доставлен, плата пытается дослать его при ближайшем подключении). Оба POST требуют `X-CSRF-Token`.

**Кто владеет прибором**

- **REST.** Прибором владеет плата: она держит набор (сторож повторяет `-sta`, если шлюз запускал набор, а гистограмм нет
  20 с), ведёт базу, при необходимости считывает калибровку перед `-sta` и сохраняет спектр на flash. REST-клиенту остаётся читать данные и
  посылать команды.
- **TCP-мост :8234** — ответвление сырого потока прибора: плата продолжает собирать собственный спектр параллельно. Клиент один
  (второй соединяется и закрывается), аутентификации нет. Любые байты, принятые от клиента, переводят намерение набора в
  «неизвестно», и сторож набора перестаёт повторять `-sta`. Команды `-rst` и `-sta … -r` от клиента после доставки прибору
  стирают спектр и базу платы. Согласования между командами TCP-клиента, Web UI и REST-клиента в коде платы не обнаружено, поэтому
  одновременно управлять прибором из нескольких каналов не рекомендуется.

## Безопасность и модель доверия

Шлюз рассчитан на **доверенную локальную сеть** (домашний Wi-Fi) и **не имеет
аутентификации пользователя** — кто угодно в той же сети может открыть Web UI,
читать спектр и управлять прибором. Это осознанный выбор для домашнего прибора
без облака и аккаунтов; не выставляйте плату напрямую в интернет.

Что всё-таки защищено:
- **CSRF-токен** на всех мутирующих POST (`/api/command`, `/api/reset`, `/api/save`,
  `/api/reboot-*`, `/api/wifi/reset`, `/api/calibration`, удаление спектров). Сторонняя
  вкладка в браузере оператора не может прочитать токен (same-origin policy), поэтому
  не может «вслепую» отправить, например, сброс Wi-Fi или перезагрузку.
- **TCP-мост** (порт 8234) — один клиент одновременно.

Чего нет (by design): TLS, логин/пароль, разграничение прав. Если нужен внешний
доступ — заводите его через доверенный канал (VPN/реверс-прокси с авторизацией),
а не пробросом порта.

**Внешние обращения:** плата выполняет SNTP-запросы к `pool.ntp.org` для синхронизации
системного времени (используется в метках времени спектров и имён файлов). Никаких других
исходящих соединений в интернет нет — спектры и данные остаются в локальной сети.

## TCP-мост (порт 8234)

Прозрачный serial-over-WiFi мост. BecqMoni или AtomSpectra на ПК подключаются
к `<IP-платы>:8234` вместо COM-порта — и работают как обычно.

- Один клиент одновременно
- Web UI работает параллельно с TCP-мостом
- `TCP_NODELAY` для минимальной задержки
- Мост прозрачно пересылает сырой поток прибора: ПК-клиент видит только набор самого анализатора с момента его последнего сброса, БЕЗ базы Web UI (AWF-3) — после обрыва питания счётчик в BecqMoni/AtomSpectra начнётся заново, даже если веб-интерфейс уже показывает непрерывный спектр.
- Кнопка **«Сброс»** в BecqMoni/AtomSpectra отправляет `-rst` через мост — плата ловит эту команду тем же путём, что и свою кнопку «Сброс» в Web UI, и **тоже чистит базу**: показания веб-интерфейса обнуляются синхронно с ПК-приложением, не остаётся «призрака» старого спектра.

## Водопад (спектрограмма)

![Web UI платы — вкладка «Водопад»: спектрограмма (время ↓, энергия →) и срез спектра](images/web-ui-waterfall.png)

Помимо живого спектра шлюз умеет копить **водопад** — последовательность спектров
через равные интервалы (каждая строка = дельта накопления за период, 8192 канала,
`uint16`). Запись идёт **на стороне платы**: включил «Старт» — и плата пишет
сегменты `.aswf` во flash сама, переживая закрытие вкладки, перезагрузку и сбой
питания (#REC-11-A1). Готовые сегменты можно смотреть прямо в браузере
(`http://<IP-платы>/waterfall`), **стримить на ПК в реальном времени** по
WebSocket, **забирать по HTTP** и сшивать в единый файл (`wf_pull_client.py` /
`wf_recorder_app.py`, #REC-12 — для многочасовых/многодневных записей без

## Протокол

Atom Spectra общается по бинарному протоколу **shproto** через USB serial (600000 бод):

| Параметр | Значение |
|---|---|
| Стартовый байт | `0xFE` |
| Escape-байт | `0xFD` (следующий байт = `~byte & 0xFF`) |
| Финишный байт | `0xA5` |
| CRC | CRC-16 Modbus (init `0xFFFF`, poly `0xA001`) |
| Команды | `0x01` гистограмма, `0x03` текст, `0x04` статистика, `0xF3` reboot |

**Калибровка**: прибор возвращает 5 коэффициентов полинома в ответ на команду `-inf`
(10 строк hex-encoded doubles + CRC32). Полином: `E(ch) = c₀ + c₁·ch + c₂·ch² + c₃·ch³ + c₄·ch⁴`.

📖 Полный справочник всех команд прибора и формата пакетов — [`PROTOCOL.md`](PROTOCOL.md).
